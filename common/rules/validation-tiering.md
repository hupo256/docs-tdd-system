# 验证力度分级：MICRO / FOCUSED / FULL

> 唯一正文源。目标是让验证成本与真实不确定性匹配；改动行数和所在业务目录都不能单独决定档位。

## 1. 执行契约（VERIFY-TIER-001）

- **Trigger**：代码改动准备执行首个格式、类型、lint、测试或构建命令时，以及任务交付前。
- **Source**：本文件。L1 只保留“不在编辑循环中重复验证”的通用原则；仓库入口和其他 L3 文件只引用本规则。
- **Loader**：`rule-router.md` 常驻提示；编码与 G6 交付场景由 `rule-index.json` 注入本文件。
- **Executor**：Agent 先按 §2 判档；正式项目由 `docs-tdd gate ... --validation-tier <MICRO|FOCUSED|FULL> --validation-tier-reason <原因>` 记录并执行相应矩阵。
- **Evidence**：交付摘要和 gate JSON 必须记录档位、理由、真实命令及 `not-required` 项；未运行不得写成 PASS。
- **Failure**：未判档时按 FULL；MICRO 任一准入条件不成立时至少升级 FOCUSED；虚报 MICRO、重复运行同一工作树状态的检查或为低价值断言重塑生产代码，进入 Review finding。

## 2. 档位判定

### 2.1 MICRO：全部条件同时成立

1. 目标单一，影响范围明确，只改局部调用点或局部表现。
2. 复用已有成熟模式，不创造新算法、新分支、新状态或新兼容路径。
3. 不修改 schema、DTO、请求/响应字段形态、公共导出、共享实现、配置、依赖或构建链。
4. 不要求多个调用点同步，不是批量替换、迁移或“所有/每个”集合操作。
5. 最终 diff 足以直接判断行为是否符合需求，不依赖运行时环境才能证明。

文件位于 auth、交易或资金目录不自动排除 MICRO；关键是本次是否**改变高风险逻辑本身**。例如在单一请求调用点把已有字段从 `loginPwd` 改为 `loginPwd: enc(loginPwd)`，若 `enc` 是既有约定、字段形态未变且未修改加密实现，可判 MICRO。修改 `enc`、密钥处理、字段契约或多接口一致性则不能判 MICRO。

### 2.2 FOCUSED

不满足 MICRO，但影响仍局部且可以用一项或少数定向检查证明，例如局部类型调整、已有测试覆盖的逻辑修复、可能产生格式问题的多行编辑。FOCUSED 不跑全仓 typecheck、lint 或测试套件。

### 2.3 FULL

修改公共/共享契约、算法与边界、权限/金额/状态机语义、schema/mapper、配置/依赖/构建链、跨模块一致性或批量集合时使用 FULL。判断不清默认 FULL。

## 3. 验证矩阵与执行节奏

| 档位 | 编辑过程中 | 实现稳定后 |
|------|------------|------------|
| MICRO | 不跑 Biome、typecheck、lint、test | 审阅最终 diff；上述命令记为 `not-required` |
| FOCUSED | 不跑验证命令 | 一次定向 Biome，并运行已经存在且能证明本次行为的相关测试；不跑全量 typecheck/lint/test |
| FULL | 不在每次编辑后重复执行 | 在最终工作树状态统一执行现有阶段门禁 |

相同 diff 状态不重复运行同一检查。后续代码变化只使与该变化相关的证据失效。命令运行时间很短也不是重复调用的理由，工具往返、规则注入和上下文切换同样属于成本。

验证档位只裁剪 Biome、typecheck、lint、测试和构建；`verify-code-rules`、项目文档 gate、最终 diff review 与安全检查不因 MICRO 而关闭。正式 MICRO gate 仍运行这些快速规则检查，并把被裁剪的命令结构化记录为 `not-required`。

## 4. 测试文件触发条件

MICRO 默认不新增 `*.test.ts(x)`，低复杂度、非共享、非公共契约的局部 utility/tool 也不因默认习惯配测试。不得为了可测性把 inline 逻辑提成导出函数，也不得 mock 一个依赖后只断言“刚写的函数调用了该依赖”。

仅在以下任一条件成立时新增或扩充测试：

- 修改公共/共享契约或跨模块不变量；
- 存在计算、分支、状态转换或边界条件；
- 有历史回归，需要锁住失败模式；
- 现有测试因真实行为变化必须同步；
- 测试能证明关键业务行为，而不是重述实现。

优先测试跨切面不变量，例如“密码请求不得携带明文字段”，而不是为每个调用点复制一份 mock 断言。

## 5. 交付透明

最终说明只列真实执行项，并显式列出因档位而 `not-required` 的检查。`not-required` 表示规则判定无需执行；`skipped` 表示本应执行但未执行，两者不得混用。PR、共享分支和发布动作仍遵守独立的 Git/交付授权与环境门禁，不用验证档位扩大操作权限。
