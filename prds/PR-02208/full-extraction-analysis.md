## 需求概述

合约后台新增"API动态费率及返佣"配置功能，支持 L1-L5 五档配置，并在手续费折扣列表中展示用户的 API 费率档位信息。

---

## 核心功能拆解

### 功能 1: 配置页面（后台）

**位置**：合约后台 → 合约配置 → 新增"API动态费率及返佣"

**页面信息**（✅ Full Extraction 能提取到）：
- 菜单路径：合约后台 - 合约配置
- 新增子页面：API动态费率及返佣
- 参考：管理后台规范
- 原型图：第 242 行

**功能描述**：
- 展示 L1-L5 五个档位的配置表格
- 表格列：档位、30天滚动API成交量(USDT)、Maker费率、Taker费率、返佣比例、操作
- 支持点击"编辑"按钮修改每个档位的配置
- 配置次日 00:00 生效

**表单验证规则**（✅ Full Extraction 能提取到）：
1. L1-L5 档位不可重复
2. 各档位成交量区间不得重叠
3. 成交量区间必须连续，不允许空档
4. 各档位采用"左闭右开"区间，最后一档为左闭区间
5. Maker/Taker 费率必须满足系统精度要求
6. 不符合规则统一报错："请输入正确的参数"

**影响文件**（✅ Full Extraction 能推断）：
- 新增页面组件：`apps/futures-admin/src/pages/ApiRateConfig/index.tsx`（推测）
- 路由配置：`apps/futures-admin/src/constants/routes.ts`
- 菜单配置：`apps/futures-admin/src/constants/menu.ts`（推测）
- 编辑表单组件：`apps/futures-admin/src/pages/ApiRateConfig/EditForm.tsx`（推测）
- API 接口：需要确认
- 预计：4-6 个文件

### 功能 2: 列表列新增（后台）

**位置**（✅ Full Extraction 能提取到）：合约后台 → 手续费 → **手续费折扣**

**定位信息**：
- PRD 第 337 行明确说明
- 原型图：第 335 行
- 在现有"手续费率"列后新增两列

**新增列**：

2. **API费率（含Maker&Taker）**
   - 有 API key 用户：显示 "Maker 0.01% / Taker 0.05%"
   - 无 API key 用户：显示 "-"

**影响文件**（❓ 需要代码搜索确认）：
- 手续费折扣列表组件：需要搜索 "手续费折扣" 或 "fee discount"
- 列定义文件
- 类型定义
- 预计：2-3 个文件

### 功能 3: 后端需求（不在前端范围，但需要知道）

**API 依赖**（✅ Full Extraction 能标记为硬阻塞）：
1. **配置 CRUD API**
   - 查询 L1-L5 配置
   - 编辑配置
   - 保存配置

2. **用户费率查询 API**
   - 获取用户的 API 费率档位
   - 获取用户的 Maker/Taker 费率
   - 判断用户是否有 API key

3. **用户 API 接口变更**（PRD 第 315-328 行）
   - 成交接口需要新增字段：rateLevel、feeRate、fee
   - 需要同步给用户侧

**阻塞严重性**（✅ Full Extraction 能识别）：
- ❌ **硬阻塞**：无配置 API 就无法实现配置页面
- ❌ **硬阻塞**：无用户费率查询 API 就无法展示列表列
- ⚠️ **建议**：等待 API 接口定义明确后再开始前端实现

## Lite 模式 vs. Full Extraction 对比

### Lite 模式遗漏的关键信息

1. **页面位置**（❌ 遗漏）
   - Lite：只知道"合约后台-合约配置模块"，但不知道具体菜单路径
   - Full：**合约后台 → 合约配置 → 新增"API动态费率及返佣"**

2. **列表定位**（❌ 遗漏）
   - Lite：不知道"手续费折扣"列表在哪
   - Full：**合约后台 → 手续费 → 手续费折扣**

3. **API 阻塞严重性**（❌ 遗漏）
   - Lite：标记了"需要 API"，但没有标记"硬阻塞"
   - Full：明确标记 **❌ 硬阻塞**，建议等待 API 定义

4. **功能范围**（⚠️ 不完整）
   - Lite：只关注前端页面
   - Full：识别出后端需求（定时任务、统计逻辑），明确前端范围

5. **技术细节**（❌ 遗漏）
   - Lite：未提取验证规则的技术细节（左闭右开、连续性）
   - Full：完整提取所有验证规则

### Full Extraction 的优势

1. **强制提取页面位置**
   - 菜单路径：合约后台 → 合约配置
   - 列表位置：合约后台 → 手续费 → 手续费折扣

2. **明确标记 API 硬阻塞**
   - 不是简单的"需要 API"
   - 而是"❌ 硬阻塞：无 API 就无法实现"

3. **完整的验证规则提取**
   - 左闭右开区间
   - 连续性检查
   - 精度要求

4. **功能范围明确**
   - 哪些是前端范围
   - 哪些是后端范围
   - 前后端边界清晰

## 结论

### Full Extraction 能解决 Lite 的问题吗？

✅ **能**。Full Extraction 会：
1. 强制提取页面位置（菜单路径、路由）
2. 明确标记 API 硬阻塞
3. 完整提取验证规则和技术细节
4. 明确功能范围和前后端边界

### 但仍然会阻塞吗？

⚠️ **部分阻塞**：
- ✅ 页面位置信息已提取 → 不会阻塞在"页面放哪"
- ✅ 列表定位信息已提取 → 不会阻塞在"列表在哪"
- ❌ API 硬阻塞仍然存在 → 仍需等待 API 定义

但至少：
- **阻塞点前置**：在 intake 阶段就识别出 API 硬阻塞
- **信息完整**：不会在实施阶段才发现缺少页面位置信息
- **可以先做调研**：可以先定位文件、创建脚手架
