# PR-02074 Web 端接口文档

## 变更范围

Web 本期新增事件搜索，并调整事件列表的固定分类筛选语义。订单创建、订单查询、持仓和结算等既有 Web 接口的请求/响应结构没有变化；本轮新增的 `conditionId/tickSize` 属于 Spot → Node 内部协议，Web 不得传入。

### 本期变化识别

| 接口/字段 | 变化类型 | 为什么增加或修改 | Web 用途 |
| --- | --- | --- | --- |
| `POST /polymarket/searchEvents` | **新增接口** | 旧事件列表没有当前语言标题模糊搜索、匹配排序和联想分页能力 | 搜索框实时联想传 5 条；“更多结果”页面传最多 50 条 |
| `POST /polymarket/getTagEventsList` | **旧接口，行为变更** | 政治/金融需要“全部”，体育需要“进行中”和用户本地日期筛选 | 分类页、体育聚合页继续调用同一路径，但按新固定分类语义传参 |
| `tagTypeThree` | **旧事件响应新增字段** | 旧响应只有一级、二级 code，无法表达“足球 → 中超/英超”等三级联赛 | 与分类树 level=3 `code` 对应，用于展示和联赛聚合 |
| `GET /polymarket/category/tree` | **旧接口，语言和数据内容变化** | 四大分类及三级体育分类不能写死在 Web；事件只保存 code | 生成分类导航，并把事件的三个分类 code 转换为当前语言名称 |
| `POST /polymarket/getEstimatedProfit` | **旧接口，计算口径和错误行为变更** | 预计收益需计入三期手续费，但费用拆分属于后端内部实现 | Web 继续读取原有预计收益字段；市场不可交易等情况停止下单 |
| `conditionId/tickSize/negRisk` | **后端内部协议字段** | Spot 调 Node Gateway 时需要权威市场参数 | Web 禁止传入，也不在页面保存 |

通用请求头：

| Header | 必填 | 说明 |
| --- | --- | --- |
| `exchange-language` | 建议 | 当前界面语言；搜索和返回标题以该值为准，缺失时使用系统默认语言 |
| `timezone` | “进行中”必填 | 用户时区，供体育“进行中”计算本地当天 00:00；不信任 body 中的 timezone |
| `X-Time` | 使用签名时必填 | 毫秒时间戳，有效期 5 分钟 |
| `X-Sign` | 按公共网络层策略 | 请求签名；前端复用现有公共签名组件，不在页面代码维护 `app_key` |
| `exchange-token` | 否 | 本文行情、搜索、分类树和预计收益接口不要求用户登录 |

`timezone` 必须是 Java `ZoneId` 可解析值，例如 `Asia/Shanghai`、`America/New_York`、`UTC+08:00`；“进行中”缺失或格式错误时返回参数错误。

鉴权说明：以上接口都经过 Web 全局 `ApiAuthInterceptor`。当前兼容逻辑在 `X-Sign` 缺失时放行；如果传入 `X-Sign`，必须同时传 5 分钟内的 `X-Time` 且签名正确，否则返回 HTTP 401、业务码 `100155`。前端应统一复用现有请求签名中间件，不应依赖省略签名的兼容行为。

## 1. 事件搜索（新增）

`POST /polymarket/searchEvents`

```json
{
  "keyword": "意大利",
  "currentPage": 1,
  "pageSize": 5
}
```

参数：

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `keyword` | string | 否 | trim 后搜索当前界面语言标题，最多 50 个 Unicode 字符；空字符串返回空列表 |
| `currentPage` | integer | 否 | 默认 1，小于 1 时按 1 |
| `pageSize` | integer | 否 | Web 联想建议 5；完整结果建议 50；服务端限制 1～50 |

`data`：

```json
{
  "list": [],
  "count": 0,
  "currentPage": 1,
  "pageSize": 5
}
```

排序：命中去重字符数降序、首个命中位置升序、推荐状态、结束时间、事件本地主键。返回列表元素沿用既有 `PolymarketEventMarketInfoRes`，没有为搜索单独新增响应 DTO。

## 2. 事件列表（接口不新增，筛选语义变化）

`POST /polymarket/getTagEventsList`

沿用既有请求体。与本期有关的字段：

```json
{
  "pageNum": 1,
  "pageSize": 20,
  "tableType": 1,
  "tagType": "sports",
  "tagTypeTow": "in_progress",
  "tagTypeThree": null
}
```

- `tagTypeTow=all`：忽略二级分类条件，查询一级分类下全部可用事件。
- `tagTypeTow=in_progress`：强制按 `tableType=1` 处理，从 `timezone` 所代表的用户本地当天 00:00 起查询仍可下注的体育比赛。
- `locale`、`timezone` 即使出现在 body 中也不作为可信值，分别由 `exchange-language`、`timezone` 请求头覆盖。
- 响应仍为既有 `data.total`、`data.list`，结构不变。
- 列表和搜索只返回至少包含一个 `active=true、closed=false、acceptingOrders=true` 可下注市场的事件。
- 事件元素新增 `tagTypeThree`，体育聚合可使用 `tagTypeTow/tagTypeThree` 取得“足球｜中超”等完整分类层级。

## 3. 分类树（协议不变）

`GET /polymarket/category/tree`

接口路径和返回结构不变；显示语言以 `exchange-language` 请求头为准。历史 `appLocale` query 参数保留兼容，但不应再作为 Web 的语言来源。

该接口不是事件列表，而是分类导航和分类名称字典。分类节点字段：

| 字段 | 新旧 | 来源和用途 |
| --- | --- | --- |
| `id` | 旧 | `polymarket_category.id`，分类数据库 ID |
| `parentId/pathIds/level` | 旧 | 分类父子关系、路径和层级；`level` 为 1/2/3 |
| `code` | 旧，稳定性增强 | 分类稳定业务键；与事件 `tagType/tagTypeTow/tagTypeThree` 对应 |
| `name` | 旧，语言来源变化 | 按 `exchange-language` 从分类 i18n 取当前显示名称，缺失时依次回退英文、中文和 code |
| `nameMap` | 旧，内容补全 | 已保存的所有语言名称，由管理端录入和翻译补偿产生 |
| `sort` | 旧 | 排序值，越小越靠前 |
| `children` | 旧，三级内容扩展 | 子分类节点；本期加入四大分类和体育三级联赛数据 |

本期没有新建分类树路径，因为既有接口已经能返回三级树；本期复用它承载 Crypto、Politics、Sports、Finance、“全部”“进行中”以及体育联赛节点，避免 Web 将分类名称和顺序写死。

## 4. 预计收益（协议不扩展）

`POST /polymarket/getEstimatedProfit`

请求和响应字段均保持不变。`marketId/tokenId/side/amount` 由服务端严格校验；市场不可交易、token 不属于市场或金额超出配置范围时返回参数错误，不再成功返回 `data=null`。

成功响应示例（BUY）：

```json
{
  "code": "0",
  "msg": "成功",
  "data": {
    "estimateProfitAmount": "169.61904761",
    "profitAmount": "69.61904761",
    "rate": "69.619000",
    "multiplier": "1.696190",
    "outcomeMap": {
      "outcomePrices": ["0.50", "0.50"],
      "clobTokenIds": ["yes-token-id", "no-token-id"]
    }
  },
  "message": null
}
```

三期手续费仍由后端内部统一报价服务计算，并反映在最终预计收益值中；平台费、Polymarket 费、预计成交价、净下单金额等中间值不返回 Web。

## 5. 事件列表字段来源及与分类树的联系

事件列表不是从分类树中生成事件。两者通过稳定 `code` 关联：

```text
分类树 level=1.code  ↔ 事件 tagType       ↔ polymarket_event.tag_type
分类树 level=2.code  ↔ 事件 tagTypeTow    ↔ polymarket_event.tag_type_tow
分类树 level=3.code  ↔ 事件 tagTypeThree  ↔ polymarket_event.tag_type_three
```

例如分类树返回 `sports → soccer → csl`，事件返回相同三个 code，Web 显示为“体育 → 足球 → 中超”。点击该分类时，把三个 code 原样传给 `getTagEventsList`，不要把中文名称作为查询参数。

| 事件响应字段 | 新旧 | 取值来源和用途 |
| --- | --- | --- |
| `id` | 旧 | `polymarket_event.id`，Spot 本地主键 |
| `eventId` | 旧 | `polymarket_event.event_id`，Polymarket 事件 ID |
| `title` | 旧，取值逻辑增强 | 按 `exchange-language` 从 `polymarket_content_i18n` 取事件译文；缺失时回退原始标题 |
| `description/icon/volume/slug` | 旧 | 来自 `polymarket_event` 本地快照 |
| `tagType` | 旧 | `polymarket_event.tag_type`，对应分类树一级 code |
| `tagTypeTow` | 旧 | `polymarket_event.tag_type_tow`，对应分类树二级 code；历史字段名不能改为 `tagTypeTwo` |
| `tagTypeThree` | **新增** | `polymarket_event.tag_type_three`，对应分类树三级 code；解决联赛级分类缺失 |
| `startTime` | 旧 | `polymarket_event.start_time`，体育比赛 UTC 开始时间 |
| `startTimeUtc0` | 旧 | 后端将 `startTime` 转为 UTC 毫秒时间戳，前端据此转换用户本地日期 |
| `endDate/endDateTmeUtc0` | 旧 | 事件结束 UTC 时间及后端换算的毫秒时间戳；`Tme` 是历史拼写 |
| `markets` | 旧 | 查询 `polymarket_market` 后按 `group_item_threshold` 组成 Map，只保留可下注市场 |
| `teams` | 旧 | 解析 `polymarket_event.teams_json`；非体育事件可能为空 |

市场字段来源：

| 字段 | 来源 |
| --- | --- |
| `markets.*.id` | `polymarket_market.market_id`；预计收益请求的 `marketId` 从这里取 |
| `question` | 市场 i18n 译文，缺失时回退 `polymarket_market.question` |
| `groupItemTitle/volumeClob/description/marketSlug` | 对应市场表快照字段 |
| `outcomes.*.outcomePrice` | `outcome_prices` JSON 数组按下标与结果名称组合 |
| `outcomes.*.clobTokenId` | `clob_token_ids` JSON 数组按下标组合；预计收益和下单的 `tokenId` 从这里取 |

`all` 和 `in_progress` 是特殊查询节点，不要求事件真正绑定到这两个 code。`all` 忽略二级条件；`in_progress` 强制体育比赛，并从用户本地当天 00:00 起筛选。

## 6. 预计收益字段来源与内部手续费口径

手续费计算和扣除是后端内部实现。C 端接口只返回最终预计收益结果，不返回平台费、Polymarket 费、预计成交价、净下单金额或预计份额等中间值。

### 6.1 请求字段和数据来源

请求字段没有新增，但来源必须固定：

| 请求字段 | 取值来源 |
| --- | --- |
| `marketId` | 事件列表 `markets.*.id` |
| `tokenId` | 用户选择的 `markets.*.outcomes.*.clobTokenId` |
| `side` | `BUY` 买入或 `SELL` 卖出 |
| `amount` | BUY 为用户投入金额；SELL 为卖出份额 |

服务端内部根据 token 匹配本地 `yes_price/no_price`；Polymarket 费率来自市场同步写入的 `polymarket_market.rate`；平台费率来自配置中心 `polymarket_buy_fee/polymarket_sell_fee`。Web 不传价格、费率或任何费用中间值。

### 6.2 响应字段来源和用途

| 响应字段 | 新旧 | 取值和用途 |
| --- | --- | --- |
| `estimateProfitAmount` | 旧，保持不变 | 计算手续费后的预计兑付金额（含本金） |
| `profitAmount` | 旧，保持不变 | 预计兑付金额减用户投入金额 |
| `rate` | 旧，保持不变 | `profitAmount ÷ amount × 100` |
| `multiplier` | 旧，保持不变 | `estimateProfitAmount ÷ amount` |
| `outcomeMap` | 旧，保持不变 | 本地 Yes/No 价格数组和对应 token 数组 |

响应没有新增费用明细字段。BUY/SELL 手续费公式、价格、费率、平台抽水、净下单金额均为后端内部实现，不属于 C 端接口协议。
