## Admin 设计原则

- 遵循现有 Ant Design 后台风格：紧凑、功能优先、克制，不做营销式视觉。
- 表格页复用现有 SearchForm + Table + Block 模式；筛选项多时保持两到三列或可折叠。
- 新增/编辑弹窗中等表单优先 `width={840}`，字段多或树结构复杂再放宽。
- 高风险操作（删除分类、下线事件、关闭交易、手动平账）必须二次确认；测试告警入口已按 PRD 删除线口径移除。
- 金额、费率、份额使用右对齐或统一格式；无数据展示 `-`。

## 状态与异常

| 场景 | UI 要求 |
|------|---------|
| loading | 表格和卡片局部 loading，不阻塞整个后台框架 |
| empty | 表格空态明确，不展示假数据 |
| error | 请求失败可重试；mutation 失败不提前更新成功态 |
| permission | 无权限隐藏操作或禁用，并遵循现有后台权限提示 |
| mutation | 保存 / 平账按钮 loading + disabled，防重复提交；真实 mutation 接入前只保留 UI 外壳或 mock 反馈 |
| dangerous action | 二次确认弹窗保留核心确认信息；页面级说明 / 解释 / mock 提示组件不展示 |

## 用户侧交互影响

- 若事件交易开关关闭，用户侧买入/卖出不可继续；前端是否需要主动禁用按钮待 API 字段确认。
- 若只由后端返回错误 toast，前端需确认错误码与中文文案。
- 前端埋点不改变现有用户交互，失败时不阻断交易主链路。

## i18n

- Admin 新文案开发阶段只维护 `apps/admin/src/i18n/locales/zh-CN/`。
- Web 用户侧若新增固定文案，只维护 `apps/web/src/i18n/locales/zh-CN/`。
- 其他语言不手动复制或占位。
- 后台配置的分类/事件多语言属于运营数据，不进前端 i18n 文件。
