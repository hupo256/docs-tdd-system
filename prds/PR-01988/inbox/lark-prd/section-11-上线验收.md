# **上线验收**

二期上线后按“灰度→功能验收→数据核对→稳定性观察→正式放量”五步推进，每一步设明确的通过标准（验收口径），任一项不达标即阻断进入下一步。

**上线方式与灰度**

- 先上预发/灰度：管理后台功能对内部运营/技术账号开放；前端用户侧按白名单或小流量（如 1%–5%）灰度。
- 灰度观察至少 1 个完整交易日（含一次自动对账与一次结算/卖出场景）后再扩量。
- 准备回滚预案：每个模块可独立开关（KV/配置），异常时单模块回退，不影响一期交易主链路。

**分模块验收清单**

| **模块** | **验收要点** | **通过标准** |
|-|-|-|
| 数据埋点 | 各点位（polymarket\_\*）在真实操作下能上报，字段完整 | 下单漏斗 6 个点位齐全、关键字段(uid/event_id/amount/status)无缺失，服务端结果事件与订单一致率 100% |
| 每日收入统计 | 三类收入、PM手续费、Gas、毛利与账务一致 | 抽样 1 个交易日，页面毛利 = 财务口径误差为 0；PM手续费按成交回执实际值入账 |
| 事件管理 | 添加事件、上下线、开关交易、三档 rate、多级分类、比赛/事件判别 | 新增事件分类与 Polymarket 一致；关闭交易后前端不可买卖；rate 改动即时生效 |
| 订单管理 | 检索与字段、订单ID↔哈希对账 | 按 UID/订单ID/哈希均可检索；失败订单资金已退回现货账户 |
| 仓位管理 | 仓位字段与状态流转 | 建仓/加仓/平仓/结算后状态与保证金、份额正确 |
| 手动平账 | FOK 平账、平账记录留痕 | 平账后差异率回落至阈值内；记录含操作人/时间/是否完成；不产生用户订单 |
| 告警配置 | 三类告警阈值可配、Lark 可达 | 改阈值后触发条件生效；测试告警 Lark 收到；持仓差异告警内容含四要素 |



**端到端核对（资金与持仓）**

1. 持仓对账：连续 3 个自动对账周期，交易所内持仓总和 = 链上钱包持仓，差异率 < 0.1%。
2. 资金闭环：买入冻结、失败退回、卖出/结算入账金额与公式一致（精度 8 位，末位舍弃）。
3. 收入归集：买入加价/卖出抽水/结算抽水分别进入对应收入账户，合计 = 收入统计页数值。
4. 成本核对：PM手续费取自成交回执实际值、Gas 据实，毛利可被财务复算。

**稳定性与性能**

- 钱包监控每分钟、对账每 5 分钟稳定执行，无漏跑；告警无漏报/误报（误报率可接受阈值内）。
- 下单失败率、成交时延在目标范围；连续 3 次下单失败能正确触发暂停与告警。
- 后台列表页检索响应在可接受时延内（如 P95 < 2s），大数据量分页正常。

**验收结论与放量**

各模块验收通过、端到端核对零差异、稳定性观察期无 P0/P1 缺陷后，由产品、技术、财务、运营四方会签确认，方可解除灰度、正式放量。验收过程与结论留档（验收报告）。

| **角色** | **验收职责** |
|-|-|
| 产品 | 功能完整性、交互与文案、验收标准是否满足 |
| 技术 | 埋点/对账/告警链路、性能与回滚预案 |
| 财务 | 收入/成本/毛利口径与账务一致性 |
| 运营 | 事件管理、平账、告警处置流程可用性 |
