## Meta

- **需求标题**：体验金手动失效管理
- **业务目标**：为运营提供手动失效体验金的能力，支持误发回收、违规处理、测试账号清理等场景
- **核心价值**：补齐体验金生命周期管理的最后一环，增强运营对异常场景的管控能力

## R1: 新增"体验金手动失效管理"页面 [CORE]

**原子性判定**：单一功能模块，独立页面

**业务规格**：
- **路径**：现货后台 → 福利中心 → 卡券记录 → 新增"体验金手动失效管理"页面
- **入口按钮**：在卡券记录页新增"手动失效"按钮（紫色），点击进入管理页面
- **页面包含**：
  - 筛选区：UID（精确搜索）、配置编码（精确搜索）、时间区间（失效操作时间）
  - 操作按钮：手动失效（主入口）、批量导出、重置、搜索
  - 列表字段：序号、UID、phone/email（脱敏）、活动名称、配置编码、体验金名称、类型、数量、**失效数量**（动态累加）、仓位占用、备注、操作人、失效时间

**关键业务规则**：
- **失效数量是动态字段**：初始 = 可用 + 委托冻结；用户平仓后持仓占用部分自动累加
- 列表展示历史失效操作记录，支持按条件筛选和批量导出
- 导出规则遵循 PR-01524 的通用导出规范

**UI 交互**：
- 空状态提示：无数据时展示空状态
- 分页：支持分页加载
- 实时刷新：失效数量字段需支持动态更新（持仓释放后自动累加）

**技术约束**：
- 权限点：`manual_invalidate_trial_fund`
- 查询性能：需支持大数据量筛选（100+ 条记录）

## R2: 添加失效任务弹窗 - 表单输入 [CORE]

**原子性判定**：单一交互流程，表单校验和提交

**业务规格**：
- **触发方式**：点击"手动失效"按钮打开弹窗
- **表单字段**：
  1. **UID 输入框**（条件必填）
     - 提示文案：`多个UID用英文逗号分隔，单次最多100个；留空则操作整批用户`
     - 支持：单/多 UID 手动输入或批量粘贴（英文逗号分隔）
     - 上限：100 个，超过禁止输入并提示 `单次操作UID不可超过100个`
     - **空值语义**：空 = 按配置编码批次，失效该批次全部用户
  
  2. **体验金配置编码输入框**（条件必填）
     - 提示文案：`多个编号用英文逗号分隔，单次最多100个；留空则操作该用户全批次`
     - 支持：单/多配置编码输入（英文逗号分隔）
     - 上限：100 个，超过禁止输入并提示 `单次操作批次，不可超过100个`
     - **空值语义**：空 = 按 UID 维度，失效该用户全部批次体验金
  
  3. **备注**（必填）
     - 提示文案：`请输入失效原因`
     - 限制：200 字符
     - 用途：记录操作原因，用于审计溯源

**核心校验规则**（双向互斥检查）：

| UID 状态 | 配置编码状态 | 触发模式 | 后端核心动作 |
|---------|------------|---------|------------|
| 有值（单/多个） | 空 | 按用户维度批量失效 | 失效指定 UID 的全部批次体验金 |
| 有值（单/多个） | 有值（单/多个） | 精确失效 | 笛卡尔积匹配：逐条校验每组「UID + 配置编码」，跳过无效配对 |
| 空 | 有值（单/多个） | 按批次维度批量失效 | 失效指定批次的全部用户体验金 |
| 空 | 空 | **拦截报错** | 提示：`"用户UID"与"体验金配置编码"不能同时为空，请至少填写一项` |

**笛卡尔积处理逻辑**（双多值场景）：
- 例：UID=[A, B]，batchNo=[X, Y] → 处理 (A,X), (A,Y), (B,X), (B,Y)
- 若某组合无匹配数据（用户未领取/批次不存在/已失效），跳过该组合
- 仅对有效配对执行失效，无效配对不入库、不产生流水

**提交前校验**：
- 配置编码格式校验：填写的配置编码不存在时，标红输入框提示 `体验金配置编码不存在`
- UID/配置编码双空校验：两者都为空时拦截提交

**交互逻辑**：
- **取消按钮**：关闭弹窗，清空所有输入，返回列表页
- **确定按钮**：校验通过后，调用后台预校验接口，弹出二次确认弹窗

## R3: 二次确认弹窗 - 风险提示 [CORE]

**原子性判定**：单一确认流程，防误操作

**业务规格**：
- **触发时机**：表单校验通过后，后台预校验完成，返回统计数据
- **展示信息**：
  - 影响用户数：正常可操作的 UID 数
  - 影响总金额：可用体验金 + 委托冻结体验金（USDT）
  - 可用体验金：立即失效部分
  - 委托冻结体验金：自动撤单回收部分
  - **仓位占用金额**：不自动平仓，单独展示（**不计入总金额**）
- **风险提示文案**：
  ```
  可用体验金将立即失效
  冻结体验金将自动撤单后失效
  仓位占用体验金不会自动平仓，需用户平仓后才失效
  ```

**交互逻辑**：
- **取消按钮**：返回添加失效任务弹窗，保留已填数据
- **确认失效按钮**：提交失效请求，执行后台失效逻辑
- **结果反馈**：Toast 提示 `操作成功`，关闭弹窗，刷新列表

**技术约束**：
- 后台预校验接口需返回：影响用户数、各状态金额统计
- 不可逆操作：确认后无法回退

## R4: 批量手动失效 - CSV 模板上传 [EXTENSION]

**原子性判定**：独立上传流程，表单的批量化版本

**业务规格**：
- **触发方式**：点击"批量手动失效"按钮打开上传弹窗
- **弹窗功能**：
  - 下载模板：提供 CSV 模板文件
  - 上传文件：拖拽或点击上传（支持 .xlsx, .xls, .csv，不超过 10MB）
- **模板字段**：
  - `uids`（条件必填）：单个或多个 UID（英文逗号分隔）
  - `couponCode`（条件必填）：体验金配置编码（英文逗号分隔）
  - `remark`（必填）：失效原因备注
- **校验规则**：
  - 不能 UID 和 couponCode 同时为空，提示：`"用户UID"与"体验金配置编码"不能同时为空，请至少填写一项`
  - 其他校验规则同 R2 的表单校验

**交互逻辑**：
- 上传成功后：自动校验模板，汇总统计数据
- 校验通过：直接进入二次确认弹窗（复用 R3）
- 校验失败：标红错误行，提示错误原因

**技术约束**：
- 单次上传最多 100 行（100 个 UID 或 100 个配置编码）
- 文件解析容错：空行跳过，格式错误行单独提示

## R5: 失效逻辑执行 - 三状态分类处理 [CORE]

**原子性判定**：核心业务逻辑，状态机转换

**业务规格**：

### 5.1 跳过处理场景（不失效、不生成流水）
- 体验金状态为【已用完】或【已过期】
- 传入 UID/批次号不存在，参数校验失败直接报错
- 持仓占用部分：仅做标记，暂缓回收，待用户平仓后自动失效

### 5.2 立即执行失效场景
- 状态为【待领取】（待使用）
- 已激活且可用的体验金数量 > 0
- 存在未成交委托冻结：自动撤单后回收

### 5.3 持仓占用处理
- **不自动平仓**：仅打标记，锁定仓位占用金额快照
- **延迟失效**：用户完成平仓后，系统自动将释放的体验金累加至"失效数量"
- **状态转换**：卡券状态保持不变（不改为"已失效"），直到仓位占用全部释放

**核心计算规则**：
- **实时累计失效金额**（动态字段）：
  - 初始值 = 可用体验金 + 委托冻结体验金
  - 用户平仓后：持仓占用释放金额自动累加
  - 用途：前端展示、财务对账

**技术约束**：
- 幂等性：每次请求生成唯一 `requestId`，重复提交自动拦截
- 事务补偿：余额扣减、状态变更、流水写入采用分布式事务最终一致性
- 失败重试：自动重试 3 次，失败进入异常队列人工兜底
- 并发控制：优先保证资金状态一致性，避免冻结与失效冲突

## R6: 数据展示与流水记录 [CORE]

**原子性判定**：数据持久化和多端展示

**业务规格**：

### 6.1 后台展示（新增）
- **体验金手动失效管理列表**：展示 R1 定义的所有字段
- **失效数量动态更新**：持仓释放后自动刷新

### 6.2 现有页面被动展示（无需前端改动）
以下路径会**自然展示**失效后的数据变化，无需专项开发：
- 现货后台 → 增值服务 → 体验金明细
- 现货后台 → 用户管理 → 合约账户历史支出
- 现货后台 → 用户管理 → 资金流水
- 现货后台 → 统计报表 → 财务审计 → 资金流水
- C 端 → 合约账户 → 资产 → 流水查询
- C 端 → 卡券列表：展示"已失效"状态标签
- C 端 → 卡券记录：流水【说明】字段展示"系统回收"

### 6.3 流水记录规则
- **后台流水**：记录操作人、失效原因、失效金额、操作时间
- **C 端流水**：展示类型为"系统回收"，不展示后台备注内容
- **审计要求**：所有失效操作必须生成流水，支持全链路追溯

**通知规则**：
- **静默处理**：不主动推送通知给用户
- **被动可见**：用户进入卡券列表/记录时可查看

## R7: 权限与安全控制 [CORE]

**原子性判定**：独立权限点，安全边界

**业务规格**：
- **权限点**：`manual_invalidate_trial_fund`
- **权限级别**：运营角色专属，需配置权限后才能访问
- **操作审计**：
  - 记录操作人账号
  - 记录操作时间（精确到秒）
  - 记录操作内容（UID、批次、失效金额、备注）
- **风险控制**：
  - 二次确认机制（R3）
  - 不可逆操作明确提示
  - 批量操作上限控制（100 条）

## Technical Constraints

### 前端技术约束
- 表单校验：UID/配置编码双向互斥校验
- 动态字段：失效数量需支持实时更新（WebSocket 或轮询）
- 大数据量：批量导出需支持分页加载
- 文件上传：CSV 解析和错误提示

### 后端技术约束
- 幂等性：requestId 机制
- 事务一致性：分布式事务最终一致性
- 并发控制：分布式锁
- 性能要求：批量操作（100 条）需在 3s 内完成

### 依赖服务
- 体验金账户服务：余额扣减、状态变更
- 委托单服务：自动撤单
- 持仓服务：仓位占用查询和监听
- 流水服务：操作记录和审计日志

---

## Risk & Edge Cases

### 业务风险
1. **误操作风险**：通过二次确认弹窗缓解
2. **数据一致性风险**：分布式事务 + 补偿机制
3. **并发冲突风险**：用户操作与后台失效并发时，优先保证资金一致性

### 边界场景
1. **双多值笛卡尔积**：UID=[A,B]，batchNo=[X,Y] → 4 组组合，跳过无效组合
2. **持仓占用延迟失效**：失效数量动态累加，需支持长时间跨度更新
3. **部分成功场景**：批量操作中部分 UID 失败，需清晰反馈成功/失败明细

### 异常处理
1. **接口超时**：自动重试 3 次
2. **数据不一致**：进入异常队列，人工兜底
3. **权限不足**：前端隐藏入口，后端拦截并返回 403
