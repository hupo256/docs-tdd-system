# 01 — 范围与分期

## 1. 背景

合约交易页（`apps/Futures`）采用 react-grid-layout v2 做整页可拖拽栅格，订单簿/最新成交、下单面板、K 线图等都是栅格 item，宽度按 **48 列比例** 分配。两个体验问题：

1. **K 线看盘区在宽屏上被挤占**：列宽随容器宽度等比放大，订单簿在宽屏（如 1920/2560）上跟着变宽（实测 2880px 容器下达 ~356px），本可留给 K 线的横向空间被占用。
2. **缺少图表分享入口**：用户无法把当前 K 线图分享到社交平台或导出图片。

## 2. 目标

| 目标 | 说明 |
|------|------|
| 增大 K 线看盘面积 | 把订单簿面板固定为 260px，宽屏上多出的横向空间全部给 K 线 |
| 提供图表分享入口 | K 线工具栏新增分享按钮，下拉提供社交分享与图片导出菜单 |

## 3. 本期做什么

| 模块 | 范围 |
|------|------|
| 订单簿面板宽度 | `xl`/`lg` 桌面断点下固定为 **260px**（不随视口比例放大）；差额由 K 线（TradingView）吸收 |
| 订单簿可交互性 | 宽度受控、禁用横向缩放；不被 localStorage 历史拖拽/缩放覆盖 |
| 分享按钮 | K 线工具栏图标簇内（设置齿轮与「最新价格」之间）新增分享图标 |
| 分享下拉 UI | 两段式菜单：社交区（X / Telegram / Discord / Facebook）+ 分割线 + 图片区（储存图片 / 复制图表图片 / 复制图片链接 / 在新页中打开图片） |
| 显隐条件 | 与同组图标一致：`!isDepth && width > 510` 才显示 |
| i18n | zh-CN / en-US 补齐分享菜单文案 |

## 4. 本期不做什么

| 不做项 | 说明 |
|--------|------|
| 分享可分享图片链接 | 「复制图片链接」需图床生成可分享图片 URL（依赖后端），本期删除该项，不做 |
| 社交分享带图片 | web intent 不支持直接携带本地图片，社交分享只带页面链接；带图需图床，本期不做 |
| 下单面板固定宽度 | 经产品确认，仅订单簿固定 260px；下单面板保持原比例（9 列） |
| `md` 及以下断点 | 平板/移动端为拆分/堆叠布局（订单簿与最新成交上下同列），固定单块会错位；且经计算 md 宽度区间内目标列数恒被回退到原列宽（无变化），故不处理 |
| 其他交易页 | 现货 / 杠杆 / 币本位 / 跟单等不在本次范围 |

## 5. 关键业务/交互规则

| 规则 | 说明 |
|------|------|
| 260px 语义 | 固定像素，跨视口宽度保持；只缩不放——当视口窄到 260px 需要的列数超过原列宽（9 列）时，回退为原比例（不挤占下单面板） |
| 受控项持久化 | 订单簿宽度由布局计算控制，用户历史拖拽/缩放缓存不影响它（避免旧缓存把宽度改回去） |
| 分享按钮位置 | 与产品截图一致：工具栏左侧图标簇尾部、「最新价格」下拉之前 |

## 6. 验收标准

1. 1440 / 1920 / 2560 等宽度下，订单簿恒为 ~260px，K 线区随视口变宽。
2. 拖动其它面板、刷新页面后，订单簿宽度不被旧缓存改变。
3. 窄屏（<1024）布局正常堆叠，不报错。
4. 工具栏出现分享图标，点击弹出 8 项菜单、分两段带分割线、图标与文案正确。
5. 宽度 <510px 或深度图模式下，分享按钮随图标簇隐藏。
6. `pnpm typecheck` 改动文件零报错；biome check 通过。

## 7. 分期

| 阶段 | 内容 | 状态 |
|------|------|------|
| P1（本期） | 订单簿固定 260px + 分享入口 UI 骨架 | ✅ 完成 |
| P2（本期） | 分享真实功能：社交跳转分享页面链接、K 线/TradingView 截图导出（储存/复制/新页打开）；删除「复制图片链接」 | ✅ 完成 |
