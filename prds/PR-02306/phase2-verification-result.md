## 抽取结果

### Atomic Requirements

#### R1: 新增"订单审核管理"页面 [CORE]

**原子性判定**：单一功能模块，独立页面

**业务规格**：
- **路径**：运营后台 → 订单管理 → 订单审核
- **页面包含**：
  - 筛选区：订单号、用户 UID、订单金额范围、创建时间
  - 列表字段：订单号、用户 UID、订单金额、创建时间、订单详情
  - 操作列：审核通过、审核拒绝、查看详情
  - 批量操作：批量审核通过、批量审核拒绝

**交互逻辑**：
- 点击「审核通过」：弹出二次确认弹窗 → 确认后状态变更为「待支付」→ 发送通知
- 点击「审核拒绝」：弹出拒绝原因填写弹窗（必填，200字以内）→ 确认后状态变更为「已取消」→ 发送通知

#### R2: 订单状态机新增「待审核」状态 [CORE]

**原子性判定**：独立的状态机变更

**业务规格**：
- **新增状态**：待审核
- **状态流转规则**：
  - 订单创建 → 若金额 > 10000 USDT → 进入「待审核」
  - 待审核 → 审核通过 → 待支付
  - 待审核 → 审核拒绝 → 已取消

#### R3: 用户通知功能 [CORE]

**原子性判定**：独立的通知模块

**业务规格**：
- **订单进入待审核**：发送站内信通知用户
- **审核通过**：发送站内信 + Push 通知
- **审核拒绝**：发送站内信 + Push 通知，包含拒绝原因

#### R4: 运营通知功能 [CORE]

**原子性判定**：独立的运营提醒模块

**业务规格**：
- **新订单进入待审核**：向审核人员发送站内信提醒
- **超时未处理**：待审核订单超过 24 小时未处理，发送催办提醒
