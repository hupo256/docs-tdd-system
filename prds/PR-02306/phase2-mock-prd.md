# 【模拟PRD】订单状态增加「待审核」状态

## 需求背景

当前订单系统缺少人工审核环节，高风险订单（金额 > 10000 USDT）需要增加人工审核流程。

## 产品方案

### 1. 新增「待审核」订单状态

在现有订单状态机中新增「待审核」状态：
- 订单创建后，若满足审核条件（金额 > 10000 USDT），订单进入「待审核」状态
- 审核通过后，订单流转至「待支付」状态
- 审核拒绝后，订单流转至「已取消」状态

### 2. 订单审核管理页面（新增）

**路径**：运营后台 → 订单管理 → 订单审核

**页面功能**：
- 筛选区：订单号、用户 UID、订单金额范围、创建时间
- 列表字段：订单号、用户 UID、订单金额、创建时间、订单详情
- 操作列：审核通过、审核拒绝、查看详情
- 批量操作：批量审核通过、批量审核拒绝

**交互逻辑**：
- 点击「审核通过」按钮，弹出二次确认弹窗
- 确认后订单状态变更为「待支付」，发送通知给用户
- 点击「审核拒绝」按钮，弹出拒绝原因填写弹窗（必填，200字以内）
- 确认后订单状态变更为「已取消」，发送通知给用户

### 3. 数据展示（现有页面自动体现）

订单状态变更后，以下页面会自动展示新的状态数据：

#### 3.1 后台订单列表页
**路径**：运营后台 → 订单管理 → 订单列表

订单状态字段会自动展示「待审核」状态，无需专项开发。

#### 3.2 后台订单详情页
**路径**：运营后台 → 订单管理 → 订单列表 → 查看详情

订单详情中的状态字段会自动展示「待审核」，历史记录会自动记录状态流转。

#### 3.3 后台订单统计页
**路径**：运营后台 → 数据统计 → 订单统计

统计报表中会自动包含「待审核」订单的数量统计。

#### 3.4 C 端订单列表页
**路径**：我的 → 订单

用户的订单列表会自动展示「待审核」状态标签。

#### 3.5 C 端订单详情页
**路径**：我的 → 订单 → 查看详情

订单详情中会展示「待审核」状态，并显示"订单审核中，请耐心等待"提示。

#### 3.6 财务对账页面
**路径**：运营后台 → 财务管理 → 订单对账

对账报表会自动包含「待审核」状态的订单。

#### 3.7 订单流水页面
**路径**：运营后台 → 订单管理 → 订单流水

流水记录会自动生成状态变更记录（待审核 → 待支付 / 已取消）。

### 4. 通知与提醒

#### 4.1 用户通知（新增）
- 订单进入「待审核」状态时，发送站内信通知用户
- 审核通过时，发送站内信 + Push 通知
- 审核拒绝时，发送站内信 + Push 通知，包含拒绝原因

#### 4.2 运营通知（新增）
- 新订单进入「待审核」队列时，向审核人员发送站内信提醒
- 待审核订单超过 24 小时未处理，发送催办提醒

## 验收标准

1. 高风险订单（金额 > 10000 USDT）自动进入「待审核」状态
2. 运营人员可在订单审核管理页面进行审核操作
3. 审核通过/拒绝后，订单状态正确流转
4. 所有订单相关页面正确展示「待审核」状态
5. 通知按规则正确发送

## 影响范围

- 新增：订单审核管理页面（需实现）
- 新增：用户通知、运营通知（需实现）
- 现有：后台订单列表、订单详情、订单统计、C 端订单列表、C 端订单详情、财务对账、订单流水（数据自然流转，无需改动）
