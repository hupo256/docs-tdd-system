# UI And Interaction — PR-02233 【用户端】安全验证校验交互优化

## 页面 / 组件

| 页面 / 组件 | 入口 | 形态 | 备注 |
|-------------|------|------|------|
| Web 登录验证码 | `/login` 第二步 | 页面 | 保留页面布局，新增真实切换弹窗 |
| Web 注册验证码 | `/register` 第二步 | 页面 | 单方式；手机注册可返回邮箱注册 |

## 登录方法弹窗

| 项 | 预期 |
|----|------|
| 标题 | 切换验证方式 |
| 副标题 | 选择一种已绑定的验证方式完成登录 |
| 顺序 | 谷歌验证码（GA）→ 邮箱验证码 → 手机验证码 |
| 说明 | GA：“30秒自动更新，无需发送”；邮箱/手机按 PRD 掩码 |
| 当前项 | 品牌描边 + “当前”标记 |
| 关闭 | X / backdrop 关闭，不改变当前方式 |
| 选择 | 点击非当前项后提交选择、关闭弹窗、更新输入页；邮箱/手机按需发码 |
| 展示条件 | 已绑定方式数量 ≥2；列表永不显示未绑定方式 |

## 注册引导

| 场景 | 预期 |
|------|------|
| 邮箱注册 | 仅邮箱验证码，不出现 GA/手机切换 |
| 手机注册 | 输入区下方显示“没收到验证码？尝试邮箱注册” |
| 点击引导 | 回注册第一步，切到邮箱输入；不保留已输入验证码 |

## 没有收到验证码弹窗

| 项 | 预期 |
|----|------|
| 入口 | 验证输入区域下方固定一个；双验证码也不重复 |
| 标题 | 没有收到验证码？ |
| Tab | 邮箱、手机始终显示；不依赖用户是否绑定 |
| 默认 Tab | 当前为手机则手机；当前为邮箱或双渠道则邮箱 |
| 邮箱说明 | 电子邮件验证码已发送至您的电子邮箱。如多次尝试仍未获取验证码，请采用以下步骤：检查垃圾箱；确认邮箱地址；邮件可能延迟，请过10分钟后再试。 |
| 手机说明 | 短信验证码已发送至您的手机。如多次尝试仍未获取验证码，请采用以下步骤：检查手机是否欠费；查看消息是否被过滤；确认手机号无误；10分钟后重试；尝试其他手机号。 |
| 操作 | 客服 icon 打开客服；“已知晓”关闭；切 Tab 不改变表单 |

## 发送控件状态

| 状态 | 文案 / UI | 可点击 | 进入 / 退出 |
|------|-----------|--------|-------------|
| initial | 获取验证码 | 是 | 初始；点击后 loading |
| loading | 三个跳动圆点 | 否 | 请求中；成功 sent，失败按错误分类 |
| sent | 验证码已发送 + info icon | 否 | 剩余秒数>0；tooltip 为“{n}秒后可重新发送验证码，有效期为10分钟” |
| resend | 重新发送 | 是 | countdown=0；点击回 loading |
| rate-limit | 保持 sent/disabled 并 toast 具体原因 | 否 | 使用后端 cooldown；重复点击不得发请求 |
| service/network error | 回到 initial 或 resend 原状态并 toast | 是 | 不启动新 countdown |

## 响应式与可访问性

- Web PC/H5 均使用现有登录/注册容器宽度；验证码六格不得横向溢出。
- 弹窗可键盘关闭时遵循现有 `Modal` 行为；方法项使用 button 语义而非仅 clickable div。
- loading/disabled 同时提供原生 disabled，不能只靠颜色。
- Tab、当前项、错误态提供可读标签，不能只靠颜色区分。
