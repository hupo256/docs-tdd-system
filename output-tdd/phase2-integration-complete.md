## 🎯 核心功能详解

### 1. 智能路由判断（lite-path-router.mjs）

#### 白名单场景自动识别

```javascript
识别模式：
✅ "把...改成..." → 纯文案修改
✅ "改颜色/间距/样式" → 样式调整  
✅ "修复typo/拼写错误" → 拼写修复
✅ "简单bug修复" → 简单bug修复

信心度：
- very-low 风险 → 95% 信心度
- low 风险 → 75% 信心度
```

#### 智能黑名单检查

**关键创新**：有条件的一票否决

```javascript
如果是纯文案/样式修改：
  黑名单关键词（登录、注册等）不自动拒绝
  
  例如：
  ✅ "把登录按钮文案改成'立即登录'" 
     → 虽然包含"登录"，但是纯文案修改，允许快速通道
  
  ❌ "修改登录逻辑，增加验证码"
     → 涉及"修改逻辑"行为变更，拒绝快速通道

黑名单类别：
- 资金: 金额、费用、充值、提现、支付、余额
- 权限: 权限、登录、注册、认证、授权
- 不可逆: 删除、禁用、注销、永久
- 后端: API、接口、后端、数据库
- 集合: 所有、全部、批量、每个
```

#### 文件数量检查

```javascript
估算逻辑：
- "多个文件/页面/组件" → 估算 5 个
- "所有/全部/批量" → 估算 10 个
- "单个/一个/这个" → 估算 1 个
- 默认 → 估算 1 个（保守）

阈值：
> 3 个文件 → 拒绝快速通道
```

### 2. 快速执行流程（lite-path-executor.mjs）

```
━━━ 🚀 快速通道执行 (V0-lite) ━━━

1️⃣  快速理解需求
    └─ 不走三阶段抽取（facts → requirements → surfaces）
    └─ 直接提取：改什么？影响哪些文件？
    └─ 文件数二次检查：> 3 个 → 自动降级

2️⃣  实现改动
    └─ 调用 AI 直接修改文件
    └─ 无需生成 work-item.json
    └─ 记录改动清单

3️⃣  定向验证
    └─ Lint 检查（只检查受影响文件）
    └─ TypeScript 检查（只检查受影响文件）
    └─ 任一失败 → 自动降级

4️⃣  自动提交
    └─ git add <files>
    └─ git commit -m "[ProjectID][lite-path] 摘要"
    └─ 标记 [lite-path] 便于事后审计

✅ 完成！耗时 2-5 分钟
```

## 🔒 安全保障

### 多层防护机制

```
Layer 1: 白名单准入
  └─ 必须匹配白名单模式
  └─ 信心度 > 80%

Layer 2: 黑名单检查
  └─ 资金/权限/不可逆操作
  └─ 行为变更关键词
  └─ 智能例外（纯内容修改）

Layer 3: 文件数量限制
  └─ 估算 > 3 个文件 → 拒绝
  └─ 实际 > 3 个文件 → 降级

Layer 4: 用户确认
  └─ 显示评估结果
  └─ 用户可选择拒绝
  └─ 默认 Yes（降低门槛）

Layer 5: 验证失败降级
  └─ Lint 失败 → 转标准流程
  └─ TypeScript 失败 → 转标准流程
  └─ 无缝切换，用户无感

Layer 6: 审计追踪
  └─ 提交信息标记 [lite-path]
  └─ 记录评估结果
  └─ 记录执行结果
  └─ 可事后复核
```

## 🚀 集成到 docs-tdd.mjs

### 建议的集成代码

在 `docs-tdd.mjs` 的 extract 命令处理前添加：

```javascript
// 在文件顶部导入
import { routeExtract } from './lib/lite-path-integration.mjs'

// 在 extract 命令处理前（第 355 行左右）
if (projectWorkflowVersion === 2 && command === 'extract') {
  // 快速通道评估和路由
  const litePathEnabled = !process.env.LITE_PATH_DISABLED
  
  if (litePathEnabled) {
    const projectRoot = resolveProjectRoot(projectId)
    const routeResult = await routeExtract(projectId, projectRoot, {
      enableLitePath: true,
      autoConfirm: false,
    })
    
    // 如果快速通道成功，直接返回
    if (routeResult.litePathSuccess) {
      console.log('\n✅ 快速通道完成\n')
      process.exit(0)
    }
    
    // 如果快速通道失败或用户选择标准流程，继续下面的标准流程
  }
  
  // 原有的标准流程代码
  const inputIndex = commandArgs.indexOf('--input')
  // ... 后续代码保持不变
}
```

### 注意事项

1. **异步调用**：`routeExtract` 是异步函数，需要 `await`
2. **错误处理**：快速通道失败会自动降级，无需额外处理
3. **兼容性**：不影响现有流程，完全向后兼容

## 💡 核心价值总结

### Phase 2 的本质

**不是简化流程，而是为低风险需求提供专属快车道**

- ❌ 不是降低质量换速度
- ✅ 是识别低风险场景，跳过不必要的保障

类比：
- 标准流程 = 货运火车（安全、严谨、慢）
- 快速通道 = 高铁（快速、安全、适合轻量货物）

### 与 Phase 1 的关系

```
Phase 1: 提高第一次理解准确性
  └─ 治本：减少遗漏
  └─ 适用：所有需求

Phase 2: 快速通道
  └─ 提效：跳过不必要的环节
  └─ 适用：低风险需求

组合效果：
  高风险需求：Phase 1（准确）+ 标准流程（严谨）
  低风险需求：Phase 1（准确）+ Phase 2（快速）
```
