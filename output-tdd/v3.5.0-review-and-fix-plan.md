## 🚨 P0 阻断问题分析

### 问题 1: extract 被快速通道劫持 ⚠️ 严重

**问题描述**:
- `docs-tdd.mjs:358` 在正常 v2 extraction 前执行 `routeExtract()`
- 成功后直接退出，旁路了所有正式流程：
  - extraction audit
  - 独立 review
  - 人工 scope approval
  - safe work context
  - checkpoint
  - 正式 verify
  - delivery truth

**根本原因**:
- 快速通道设计为"绕过"而非"简化"
- 没有集成到 v2 状态机中

**风险等级**: 🔴 P0（会破坏整个质量保障体系）

**修复策略**:
```
选项 A（推荐）: 默认关闭快速通道
- 添加 --enable-lite-path 标志
- 默认走标准流程
- 只在明确标记时启用

选项 B: 重新设计快速通道
- 集成到 v2 状态机
- 保留 audit/review/approval 的简化版
- 不旁路核心保障
```

---

### 问题 2: 快速执行器未真实实现却自动提交 ⚠️ 严重

**问题描述**:
- `lite-path-executor.mjs:128` 需求理解是 TODO
- `implement():162` 不修改业务文件，只返回模拟结果
- `commit():244` 却执行真实的 git add 和 git commit

**根本原因**:
- 开发未完成就集成
- 测试是模拟的，生产会出错

**风险等级**: 🔴 P0（会提交空的或错误的 commit）

**修复策略**:
```
立即行动:
1. 移除自动 commit 功能
2. 标记为 TODO / 未完成
3. 快速通道只能评估，不能执行
```

---

### 问题 3: 执行目录不是业务 worktree ⚠️ 严重

**问题描述**:
- `lite-path-integration.mjs:161` 使用 `docs_tdd/prds/<ID>` 项目文档目录
- 没有校验：
  - 业务分支
  - worktree
  - dirty scope
  - 冻结路径
  - 用户已有改动

**风险等级**: 🔴 P0（会提交错误文件）

**修复策略**:
```
必须改为:
1. 使用业务 worktree 目录
2. 校验 safe work context
3. 检查 dirty scope
4. 验证路径合法性
```

---

### 问题 4: 外部 PRD 内容可进入 shell 命令 🔒 安全

**问题描述**:
- `lite-path-executor.mjs:252` 将 PRD 文本拼进 `git commit -m "..."`
- 双引号、反引号、`$()` 可能造成命令注入
- 文件路径在 lint、tsc、git 命令中同样存在

**风险等级**: 🔴 P0（安全漏洞）

**修复策略**:
```javascript
// ❌ 错误（字符串拼接）
spawnSync('git', ['commit', '-m', `"${message}"`], { shell: true })

// ✅ 正确（argv 数组）
spawnSync('git', ['commit', '-m', message], { shell: false })
```
