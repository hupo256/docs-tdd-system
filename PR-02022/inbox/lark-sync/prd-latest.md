# 三、需求背景

### 3.1 核心问题

1. **新用户无引导：** 新用户首次进入跟单广场，缺乏步骤化的引导流程，用户容易因不了解玩法而流失，未能完成首次跟单动作；
2. **带单员身份感知弱：** 用户申请带单员通过后，缺乏明确的强提醒通知，用户不清楚自己已具备带单资格，导致带单员激活率低；
3. **广场数据质量差：** 当前跟单广场存在"尚未产生任何带单数据的带单员"出现在列表中的情况，影响跟单者的决策质量与平台信任感。

### 3.2 优化目标

1. 新增新手引导
2. 每次成为带单员身份强提醒弹窗
3. 通过交易员可见性控制逻辑，保障跟单广场的数据质量，仅展示已有真实带单数据的交易员。

# 五、产品方案_跟单者视角

## 5.1 【新增】引导功能

**操作路径：**【web】--【合约跟单】--初次进入【跟单广场页】

**功能说明：** 用于引导初次进入跟单广场的用户**快速了解跟单玩法并完成首次跟单动作**。当用户**首次访问**跟单广场页时，**触发三步引导流程**，通过步骤化的文案与交互提示，降低用户认知门槛，尽可能的提升首次跟单转化率。

> 📷 图片：合约跟单广场页截图，红框标注引导入口位置（L/S 图标区域）。

### 触发条件

- 已登录 + 首次进入跟单广场页，全生命周期仅触发一次
- 页面主体加载完成后展示，未登录不触发
- 无论跳过还是完成，后续进入均不再展示

### 引导步骤说明

| 步骤 | 标题 | 正文 | 按钮逻辑 |
|------|------|------|---------|
| 第一步 | 选择带单员 | 从众多优质交易员中，挑选最适合你的 | **跳过**：状态→已结束，弹窗关闭；**下一步**：切换至第二步 |
| 第二步 | 一键配置，轻松入场 | 设定跟单金额及相关参数，立即跟单 | **跳过**：状态→已结束，弹窗关闭；**上一步**：回到第一步；**下一步**：切换至第三步 |
| 第三步 | 跟单进展，尽在掌握 | 实时查看持仓与收益，随时调整跟单策略 | **上一步**：回到第二步；**完成**：状态→已完成，弹窗关闭 |

**注⚠️：** 【上一步/下一步】**仅切换弹窗内容**，不更新状态；用户**【中途退出页面】未操作跳过/完成**，状态不更新，下次进入重新从第一步展示。

### 前后端处理逻辑

#### 3.1 用户的引导状态

| 状态值 | 说明 |
|--------|------|
| 未触发 | 默认值 |
| 已结束 | 用户点击跳过 |
| 已完成 | 用户点击完成 |

> 状态一旦变更为**【已结束/已完成】后则**不可逆，也不重置。

#### 3.2 前后端接口

| 时机 | 前端行为 | 后端处理 |
|------|---------|---------|
| 进入跟单广场页 | 查询引导状态 | 按用户 ID 返回当前状态 |
| 状态=未触发 | 页面加载完成后展示第一步弹窗 | — |
| 状态=【已结束/已完成】 | 不展示引导 | — |
| 点击【跳过 或 完成】操作 | 调接口上报状态变更，关闭弹窗 | 用户维度：记录【已结束 或 已完成】的状态（状态不可逆转变更） |
| 接口异常 | 默认不展示引导，不影响主流程 | 底层记录详细日志（便于追踪解决问题） |

## 5.2 【新增】成功"成为带单员"后的弹窗

**操作路径：**【web】--【合约跟单】--进入【跟单广场页】

**功能说明：** 用于"明确的告诉用户"，强提醒，让用户**明确感知**"带单员的申请已经通过了"，现在可以去带单了。

> 📷 图片：带单员弹窗截图，绿色勾选图标，紫色"点击进入"按钮。

### 触发条件

- 已登录 + 身份为合约带单员 + 首次进入跟单广场页
- 全生命周期仅触发一次，关闭后后续进入不再展示
- 页面加载完成后展示，与新手引导弹窗互斥（**两者同时满足时：** 仅展示本弹窗即可，无需展示新手引导）

### 强提醒的弹窗内容说明

| 字段 | 说明 |
|------|------|
| 标题 | 恭喜您 |
| 内容 | 您已成为合约带单员！完成首笔带单后，您的主页将正式展示在带单员列表中，赶快开始您的第一笔带单吧！ |
| 操作 - ×（关闭） | 点击后弹窗关闭，停留在跟单广场页；**状态：已读**；点击非弹窗区域不可取消弹窗 |
| 操作 - 去带单 | 点击后弹窗关闭，跳转至**带单交易页面**；**状态：已读** |

### 前后端处理逻辑

#### 3.1 弹窗状态

| 状态值 | 说明 |
|--------|------|
| 未读 | 默认值，用户尚未看过此弹窗 |
| 已读 | 用户点击过 × 或去带单，后续不再展示 |

> 状态一旦变更为**【已读】后则**不可逆，也不重置。

#### 3.2 前后端接口

| 时机 | 前端行为 | 后端处理 |
|------|---------|---------|
| 进入跟单广场页 | 查询弹窗状态（同时校验用户是否为带单员） | 按用户 ID 返回**带单员身份** + **弹窗状态** |
| 身份=带单员 且 状态=【未读】 | 页面加载完成后展示弹窗 | — |
| 点击：× 或 去带单 | 调接口上报状态→已读，执行对应跳转/关闭 | 用户维度：记录【已读】的状态（状态不可逆转变更） |
| 接口异常 | 默认不展示弹窗，不影响主流程 | 底层记录详细日志（便于追踪解决问题） |

由于上方已针对【成为交易员后首次进入跟单广场】的场景新增了【成为交易员的弹窗】，那么**现状流程中对应的旧引导逻辑（见下图一）需同步移除。**

⚠️ 注：仅移除「成为交易员后」进入跟单广场的**旧流程节点**，跟单广场页面本身（下图二）千万别干掉。（因为其他地方有用到的）

## 5.3 【跟单广场】的交易员可见性逻辑

**功能说明：** 控制带单员在跟单广场的**展示与搜索可见性**，避免"无带单数据的交易员"出现在广场列表中，影响跟单者的决策质量。

### 可见性判断逻辑

| 判断条件 | 是否在广场展示 | 是否可被搜索 |
|---------|-------------|------------|
| 已成为带单员身份 + 已产生带单数据【该带单员名下是否存在至少 1 笔已开仓的带单仓位记录（无论是否已平仓）】 | 是 | 是 |
| 已成为带单员身份 + **尚未产生任何带单数据** | 否 | 否 |
| 带单员**项目已关闭**（目前没有关闭项目，现在只需要看"是否为带单员的开关"）| 否 | 否 |
| **带单员首次开仓后：实时更新可见状态**，该交易员出现在跟单广场**列表及搜索结果中** | 是 | 是 |

> 📷 图片：合约跟单广场页，红箭头指向"开通交易"开关（带单员可见性开关说明）。

### 【带单员自身视角】【跟单者视角】前端展示说明

| 场景 | 展示逻辑 |
|------|---------|
| 跟单广场列表 | 仅展示"**已产生带单数据**的交易员，**无带单数据的交易员**不出现在任何列表分组中（顶级交易员列表 / 交易员列表均不展示）" |
| 跟单广场搜索 | 搜索"**无带单数据的交易员用户名时**，返回空结果，不展示该交易员卡片" |

## 5.4 埋点

> 埋点范围：5.1 新手引导 + 5.2 带单员弹窗 + 5.3 交易员可见性（搜索行为）

| 事件名称 | 触发时机 | 关键参数 | 备注 |
|---------|---------|---------|------|
| copytrade_guide_show | 新手引导弹窗曝光（第一步展示） | user_id、step=1 | 每次触发仅上报一次，不含翻页 |
| copytrade_guide_step_view | 用户切换至某一步骤时 | user_id、step（1/2/3） | 包含初次展示的第一步 |
| copytrade_guide_skip | 用户点击【跳过】 | user_id、skip_step（从哪步跳过，取当前那一步的值） | — |
| copytrade_guide_complete | 用户点击【完成】 | user_id | — |
| copytrade_guide_prev | 用户点击【上一步】 | user_id、from_step | — |
| copytrade_guide_next | 用户点击【下一步】 | user_id、from_step | — |
| trader_become_popup_show | 带单员身份弹窗曝光 | user_id | — |
| trader_become_popup_close | 点击 × 关闭弹窗 | user_id | — |
| trader_become_popup_go_trade | 点击【去带单】 | user_id | — |

**说明：**
- 所有事件均携带基础公参（platform、page_name、time）
- `step` 参数从 1 开始计数，与引导步骤序号一致
- `skip_step` 记录用户从第几步点击跳过，用于分析各步骤流失率
