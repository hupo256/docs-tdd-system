## TDD / PRD / API 冲突或待确认

| 项 | PRD | TDD / YApi | 结论 |
|----|-----|------------|------|
| 活动 ID 命名 | 活动页路由使用 `activityId` | YApi path 使用 `campaignId` | 已有建议：页面保留 `activityId`，service 映射为 `campaignId` |
| 倒计时实现 | PRD 原文写 WebSocket 实时/定时轮询 | 评论确认不需要 WebSocket，服务端返回时间戳，客户端本地计算 | 已确认：Banner 倒计时 / 自动开启 / 自动结束不接 WebSocket |
| 时间字段 | PRD 要服务端校准时间、倒计时 | YApi 2026-06-26：详情返回 `serverTime` + 毫秒时间戳；列表接口仍为 string date-time | 详情侧已明确；列表/详情时间类型不一致待联调 |
| 排行榜分页 | PRD 要分页 | YApi 仍仅 `displayLimit`；新增 `refreshIntervalMinutes`/`lastUpdatedTime` | 前端本地分页 + 用新字段展示更新时间 |
| 活动规则格式 | 配置多少展示多少 | `ruleContent` + 新增 `ruleTitle` | 渲染格式仍待联调 |
| 资格拦截原因 | 限定用户、受限地区、黑名单、KYC | `joinButtonStatus` + `rejectReason`（含 `NOT_IN_AUDIENCE`/`KYC_NOT_PASSED` 等） | 联调验证 BLOCKED 场景 |
| 分享配置 | PRD 要分享链接+邀请码 | YApi 已移除 `shareConfigJson` | 前端按活动 ID + 现有邀请体系拼装 |
| 任务进度实时性 | PRD 要活动有效期变化和进度同步 | YApi 有 `refresh` / `progress`，WebSocket 未见 | 暂按 React Query 轮询和手动刷新；仅任务/排行榜 WebSocket 待确认 |
| 数据统计边界 | Lark QA 要求前端记录浏览、点击、分享、规则、任务按钮等行为 | 后端记录报名成功、任务完成、领奖成功、发奖成功和失败 | 已确认：Web 前端只接行为埋点；后台报表、后端业务事件、发奖重试与人工处理不属于 Web 落地页实现范围 |
