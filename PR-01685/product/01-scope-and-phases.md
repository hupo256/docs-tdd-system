# 01 — 范围与分期

## 1. 背景

当前活动通常需要单独开发，存在三类问题：

1. **开发成本高**：每个活动单独开发，重复消耗时间和人力。
2. **承载能力弱**：公告/海报类活动只能静态展示，无法承载任务进度、奖励说明、资格校验、领取入口等完整链路。
3. **数据闭环缺失**：活动数据需要人工拉取和拼表统计，复盘成本高且容易口径不一致。

本需求希望沉淀一套统一活动展示框架，由后台配置活动、子活动、任务组合、任务条件和奖励，Web 前端负责展示与触发用户行为。

## 2. 目标

| 目标 | 说明 |
|------|------|
| 统一活动展示框架 | 支持 5 种任务类型在 Web 端统一展示 |
| 任务进度可视化 | 实时展示用户当前值 / 目标值与进度条 |
| 奖励状态透传 | 展示待领取、已领取、已发放、待发放、已结束等状态 |
| 多任务多模块支撑 | 同一活动支持多个子活动，子活动内支持多个任务组合 |
| 操作闭环 | 报名 → 做任务 → 领取奖励 → 查看奖励记录 / 卡券中心 |

## 3. Web v1 做什么

| 模块 | Web v1 范围 |
|------|-------------|
| 活动入口 | 支持运营 Banner 进入活动落地页；个人中心活动中心为二期 |
| 活动详情路由 | 根据活动 ID 打开活动落地页，路由已确认：`/campaign/[activityId]` |
| Banner / 头图 | 展示后台配置头图、标题、副标题、时间、倒计时、分享 |
| 活动状态 | 未开始、进行中、已结束 |
| 报名 | 未登录跳登录；进行中可报名；已报名置灰；已结束置灰 |
| 资格限制 | 非限定用户、受限地区、黑名单用户弹强拦截弹窗并返回上一页 |
| 子活动 | 展示子活动标题、副标题、多个任务组合 |
| 单一任务 | 展示奖励、条件、进度、行动按钮、领取状态 |
| 阶梯任务 | 支持 2-8 档；每档 2-3 条 AND 条件；按最高档发放，不叠加 |
| 进阶任务 | 支持 2-8 档；逐档解锁，可叠加领取 |
| 组合任务 | 支持 2-3 条条件，AND / OR 关系 |
| 排行榜任务 | 我的排名、排名指标、奖励说明、排行榜、分页、更新时间、空态 |
| 活动规则 | 页面底部完整展开，支持锚点平滑滚动 |
| 底部浮层 | 顶部主按钮不可见时展示引导浮层；可报名 / 已报名 / 已结束状态同步 |
| 分享 | Web 端固定渠道：保存、复制链接、WhatsApp、X、Telegram |
| 异常状态 | 首屏骨架屏、接口失败提示、领取超时提示、重复领取幂等展示 |

## 4. Web v1 不做什么

| 不做项 | 说明 |
|--------|------|
| App 页面 | PRD 包含 App，但本次只开发 Web |
| 管理后台 | 活动配置、子活动配置、任务配置、报表后台不在 Web 落地页范围 |
| 个人中心活动中心 | PRD 定义为二期 |
| App 分享渠道 IP 差异 | 仅 App 逻辑，Web 固定渠道 |
| 奖励实际发放 | 发奖由后台接口处理，前端只触发领取和展示状态 |
| 后端排名计算 | 前端只展示后端返回排名数据 |
| 活动数据报表 | 独立数据统计需求文档，本文档只记录前端埋点待接入 |

## 5. 业务规则

### 5.1 活动生命周期

| 状态 | 判断 | 前端表现 |
|------|------|----------|
| 未发布 | 后端不可见 / 不返回 | 前端不可见，若访问需按后端错误处理 |
| 未开始 | 服务端校准后的当前时间 < 开始时间 | 倒计时距开始；主按钮置灰“未开始” |
| 进行中 | 开始时间 ≤ 服务端校准后的当前时间 < 结束时间 | 展示任务并允许报名、任务跳转、领取 |
| 已结束 | 服务端校准后的当前时间 ≥ 结束时间 或已下线 | 主按钮“已结束”置灰；任务只读；底部展示奖励陆续发放文案 |
| 已下线 | 后端标记下线 | PRD：前端展示“已结束” |

### 5.2 报名按钮

| 用户 / 活动状态 | 行为 |
|-----------------|------|
| 未登录点击“立即参与” | 跳转登录页，携带 from 回跳 |
| 未完成 KYC 且活动要求 KYC | toast：该活动需先完成身份认证后，才可参与 |
| 未报名 + 活动未开始 | 按钮展示“未开始”并置灰 |
| 未报名 + 活动进行中 | 调报名接口，成功 toast：已报名成功；按钮改“已参与”置灰 |
| 未报名点击任意任务按钮 | toast：请先点击【立即参与】报名活动后，即可参与 |
| 已报名 | 按钮展示“已参与”置灰 |
| 已结束 | 按钮展示“已结束”置灰 |

### 5.3 条件类型与动作

| 条件类型 | 是否进度条 | 默认动作 |
|----------|------------|----------|
| KYC | 否 | 去身份认证页 |
| 净充值额 | 是 | 去充值页 |
| 累计充值额 | 待确认：PRD 单一任务列出但进度条表未列出 | 去充值页 |
| 现货交易量 | 是 | 去 BTC 现货交易页 |
| 合约交易量 | 是 | 去 BTC 合约交易页 |

### 5.4 奖励按钮状态

| 状态 | 按钮文案 | 交互 |
|------|----------|------|
| 条件未完成 | 去完成 | 跳转后台配置动作 |
| 条件已完成 + 手动领取 | 待领取 | 点击领取奖励 |
| 已领取待发放 | 已领取 | 置灰 |
| 发放完成 | 已发放 | 置灰 |
| 自动发放且已完成待发放 | 待发放 | 置灰 |
| 活动已结束 | 已结束 | 置灰 |

## 6. 验收标准（Web）

- [ ] 活动详情页可通过约定路由访问。
- [ ] 活动头图、标题、副标题、时间、倒计时、状态展示正确。
- [ ] 未开始 / 进行中 / 已结束状态切换正确。
- [ ] 未登录点击报名或任务操作跳转登录并携带 from。
- [ ] 报名成功后按钮改为“已参与”，任务可操作。
- [ ] 非限定用户 / 禁止地区 / 黑名单用户进入页面后弹强拦截弹窗，点击后返回上一页。
- [ ] 单一、组合、阶梯、进阶、排行榜五种任务均能根据 API 数据正确渲染。
- [ ] 数值条件展示当前值 / 目标值 / 进度条；KYC 条件不展示进度条。
- [ ] 领取成功、重复领取、超时、失败均有符合 PRD 的反馈。
- [ ] 排行榜展示我的排名、指标、奖励说明、分页、最近更新时间与暂无数据空态。
- [ ] 活动规则完整展开，点击头部“活动规则”平滑滚动到底部规则区。
- [ ] 页面下滑且顶部主按钮不可见时展示底部浮层，回到顶部隐藏。
- [ ] 分享弹窗 Web 固定渠道可用，复制链接包含活动 ID 与邀请码。
- [ ] 首次加载展示骨架屏，不白屏。
- [ ] 相关接口有 loading / error / disabled 状态。
- [ ] i18n 开发期仅维护 zh-CN。
- [ ] 相关 mapper / 计算逻辑有单测。

## 7. 分期建议

| 阶段 | 内容 |
|------|------|
| Sprint 0 | 文档确认、API 契约确认、UI 走查、路由确认 |
| Sprint 1 | 路由、活动详情接口、Banner、报名、限制弹窗、规则区、底部浮层 |
| Sprint 2 | 单一 / 组合 / 阶梯 / 进阶任务渲染与领取 |
| Sprint 3 | 排行榜任务、分享弹窗、埋点、异常与轮询 |
| Sprint 4 | UI 还原、联调、验收、补测试 |
