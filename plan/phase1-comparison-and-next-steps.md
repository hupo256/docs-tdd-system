# Phase 1 效果对比与下一步建议

## 一、新旧指南对比

### 旧版 instructions（v3.4 及之前）
```javascript
instructions: [
  'Stage A — facts: enumerate source-grounded actions...',
  'Stage B — requirements: map every fact...',
  'Stage C — surfaces: expand every doing requirement...',
  // ... 共 9 条简短指令
]
```

**特点**：
- ✅ 简洁明了
- ❌ 缺乏"如何精读"的指导
- ❌ 没有强制枚举要求
- ❌ 没有图片深度解读协议
- ❌ 没有自我检查环节
- ❌ 没有历史教训警示

### 新版 extractionGuidance（v3.5 Phase 1）
```javascript
extractionGuidance: `
  # 需求抽取指南 v2.0（精读版）
  
  四遍精读法（强制遵循）
  - 第 1 遍：全局扫描
  - 第 2 遍：分主题深入（高风险优先、集合强制枚举）
  - 第 3 遍：富媒体深度解读
  - 第 4 遍：自我完整性检查
  
  历史遗漏教训（3 个案例）
  
  领域检查清单（自动激活）
  - 资金类、权限类、集合类、列表类、表单类
  
  // 共 ~6000 字符，189 行
`
```

**特点**：
- ✅ 详细具体的操作指南
- ✅ 强制枚举协议（"所有"必须完整列举）
- ✅ 图片深度解读（5 个问题）
- ✅ 自我完整性检查（4 个维度）
- ✅ 历史案例警示（3 个教训）
- ✅ 领域检查清单自动激活
- ✅ 理解摘要输出（用户 10 秒确认）

## 二、关键差异示例

### 案例 1：集合枚举（PR-01930 教训）

**旧版处理**：
```
PRD: "修改所有登录入口"
AI: 找到 2 个入口就停了
→ 漏掉第 3 个
```

**新版处理**：
```
PRD: "修改所有登录入口"

extractionGuidance 明确要求：
  "遇到'所有'、'每个'必须完整列举：
   1. 识别枚举目标
   2. 完整列举（PRD + 业务常识 + 代码搜索）
   3. collectionSemantics.expectedCount 标记数量
   4. affectedSurfaces 逐个列出"

AI 应该：
  - 思考：有哪些登录入口？
  - 列举：账号密码、手机号、第三方、忘记密码、注册
  - 输出：expectedCount: 5，5 个 surfaces
→ 不会遗漏
```

### 案例 2：图片解读（PR-02306 教训）

**旧版处理**：
```
图片：显示密码输入框，下方有小字"8-20位，必须包含字母和数字"
AI: "这是登录页截图，包含密码输入框"
→ 只描述元素，漏掉规则
```

**新版处理**：
```
extractionGuidance 明确要求：
  "图片深度解读（每张必须）：
   不合格：只描述元素
   合格：提取需求
   
   对每张图片问 5 个问题：
   1. 传达什么需求？
   2. 哪些信息是文字中没有的？
   3. 如果我不看这张图，会漏掉什么？"

AI 应该：
  R-IMG-001（图片文字）：
    密码输入框下方提示："8-20位，必须包含字母和数字"
    → 需求：密码长度 8-20，必须字母+数字组合
    → PRD 文字中未提及此规则 ⚠️
    → 标记为【图片独有需求】
→ 不会遗漏
```

### 案例 3：领域检查（PR-02265 教训）

**旧版处理**：
```
PRD: 涉及金额、费用字段
AI: 快速扫描，关键字段被淹没
→ 漏掉 amount/fee
```

**新版处理**：
```
detectDomainSignals() 自动检测到"金额"、"费用"关键词
→ 激活【资金类】检查清单：
  - □ 金额字段：类型、单位、精度
  - □ 余额检查：是否检查余额充足
  - □ 不可逆确认：是否有二次确认弹窗
  - □ 异常处理：余额不足如何处理
  - □ 审计日志：是否记录操作
  - ...

AI 必须逐项确认
→ 不会遗漏
```

## 五、风险与注意事项

### 风险 1：Guidance 太长影响 AI 理解

**现状**：extractionGuidance ~6000 字符（189 行）

**缓解**：
- 当前在合理范围内（< 10K 字符）
- 如果发现 AI 不遵循，可以：
  - 压缩表述，保留核心
  - 或在 instructions 中强调"必须严格遵循"

### 风险 2：AI 仍然不遵循详细指南

**可能原因**：
- AI 倾向于快速扫描，即使有详细指南
- Prompt Engineering 有局限性

**缓解**：
- 在 instructions 中强调"强制遵循"、"不要跳过"
- 如果仍然无效，考虑双 Agent（一个抽取，一个验证）

### 风险 3：理解摘要增加用户负担

**缓解**：
- 格式简洁，10 秒能确认
- 输出到 stderr（不影响 JSON 管道）
- 如果用户觉得多余，可以加 --no-summary 选项
