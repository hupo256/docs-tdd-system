## 回答你的三个核心问题

### 1. 小改动用大量时间和 token

**v4.0 解决方案**：lite-path 快速通道

- ✅ kickoff 从 ~8 分钟降到 **15ms**（32,000x 提速）
- ✅ 跳过 extraction / coverage review / scope approval
- ✅ 产出最小 work-item.json（2 个文件 vs 10+ 文件）
- 🟡 规则裁剪（待集成到 Agent context，见步骤 2）
- 🟡 precommit 守卫分档（已实现，待真实 commit 验证）

**预期后续效果**：
- 小改动总耗时：8.5 分钟 → **< 2 分钟**
- token 消耗：~150K → **~30K** (-80%)

### 2. 提测时漏明显功能

**v4.0 现状**：lite-path 不解决这个问题（它跳过了 extraction/coverage）

**解决方案在第 2 周**：
- extraction checklist（防 Agent 抽漏）
- surface expectPath 必填（防「声明了没写」）
- pre-delivery self-check（防「漏功能就提测」）

**建议**：标准流程（非 lite-path）仍需第 2 周改进才能防漏需求

### 3. Claude/Codex 变慢

**v4.0 解决方案**：rule-loader-v4 按档位裁剪

- ✅ 规则裁剪器已实现（micro: 12K, lite: 24K, standard: 80K）
- 🟡 待集成到 Agent context 生成（见 V4.0-INTEGRATION.md 步骤 2）

**集成后预期**：
- Claude prefill 时间：30 秒 → **5-10 秒**（lite 档）

## 风险与限制

### 已知限制

1. **lite-path 只适合低风险场景**
   - ✅ 纯文案/样式/typo
   - ❌ 涉及资金/权限/登录/不可逆操作
   - ❌ 文件数 > 3

2. **v1 项目不受益**
   - v4.0 只对 v2 项目生效
   - 建议：新需求统一走 v2（kickoff-v4 已默认 v2）

3. **规则裁剪未完全集成**
   - rule-loader-v4 已实现，但未接入 Agent context 生成
   - 需要手动集成（见步骤 2），预计 10-15 分钟
