### 步骤 2：集成 rule-loader-v4 到 Agent context 生成

**方案 A：修改 rule-context.mjs**（推荐，适合已有 rule 加载逻辑）

找到现有的规则加载代码（可能在 `rule-context.mjs` 或 `rule-router.md` 的解析器），加入：

```javascript
import { generateRuleContext } from './lib/rule-loader-v4.mjs'
import { readFileSync } from 'node:fs'
import { join } from 'node:path'

// 读取 work-item.json 获取 efficiencyRoute
function loadRulesForProject(projectId, projectDir) {
  const workItemPath = join(projectDir, 'work-item.json')
  let efficiencyRoute = 'standard' // 默认
  
  if (existsSync(workItemPath)) {
    try {
      const workItem = JSON.parse(readFileSync(workItemPath, 'utf-8'))
      efficiencyRoute = workItem.efficiencyRoute || 'standard'
    } catch { /* use default */ }
  }
  
  // v4.0: 按档位裁剪规则
  const ruleContext = generateRuleContext(efficiencyRoute, {
    rulesRoot: join(projectDir, '../../common/rules'),
  })
  
  return ruleContext
}
```

**方案 B：Agent prompt 里直接调用**（更简单，适合快速验证）

在给 Agent 的 context 生成脚本里：

```bash
#!/bin/bash
# generate-agent-context.sh

PROJECT_ID=$1
EFFICIENCY_ROUTE=$(jq -r '.efficiencyRoute // "standard"' prds/$PROJECT_ID/work-item.json 2>/dev/null)

# 生成裁剪后的规则
node common/engine/agent-scripts/lib/rule-loader-v4.mjs --generate $EFFICIENCY_ROUTE > /tmp/rules-context.txt

# 拼接到 Agent prompt
cat <<EOF
# Project Context

$(cat prds/$PROJECT_ID/README.md)

# Rules (${EFFICIENCY_ROUTE} tier)

$(cat /tmp/rules-context.txt)

# Next Action

...
EOF
```

## 常见问题

### Q1: lite-path 如何判断是否适合？

**A**: 由 `lite-path-router.mjs` 的白名单和黑名单决定：

白名单（eligible=true）:
- 纯文案修改
- 样式调整（颜色/间距/字号）
- typo 修复
- 文件数 ≤ 3

黑名单（一票否决）:
- 涉及资金、权限、登录、不可逆操作
- 涉及 API/后端/数据库
- 批量/全部/所有（集合操作）

### Q2: 如果 lite-path 误判怎么办？

**A**: 三种处理方式：

1. **kickoff 时强制 standard**:
```bash
docs-tdd kickoff PR-xxx --force-standard --prd "..." --intent "..."
```

2. **手动修改 work-item.json**:
```json
{
  "efficiencyRoute": "standard"  // 改成 standard
}
```

3. **反馈给系统**，改进 lite-path-router 的判断规则

### Q3: 现有 v2 项目如何受益？

**A**: 手动在 work-item.json 加字段：

```json
{
  "efficiencyRoute": "lite"  // 或 micro / standard / high-risk
}
```

下次 commit 就会按新档位走。

### Q4: v1 项目怎么办？

**A**: v1 不受益于 v4.0。建议：

- 新需求统一走 v2（v4.0 kickoff 已默认 v2）
- 老项目继续用 v1，或手动迁移到 v2（工作量较大）
